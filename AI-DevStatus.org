* Key Design Decisions
  - Upstream tarballs, pinned + SHA-256 per Debian architecture, not Debian's 2.x package.
  - node_exporter is part of this capability (the server scrapes it out of the box) and runs as the
    prometheus account, as Debian's package does; its port has no .here name.
  - Usage side = promtool, which ships only in the Prometheus tarball: the usage sbom unpacks the same
    pinned tarball (whichever sbom runs first unpacks it). Python libraries (prometheus-client,
    prometheus-api-client) belong to each consumer's venv.
  - No login: loopback-only listeners; nginx proxies to 127.0.0.1, not to the .here address.
  - Flags in /etc/default/* as ARGS, expanded by $ARGS (word-split) in ExecStart; ExecReload=SIGHUP.
  - Config written only when absent; driftCheck reports (unified diff for YAML) instead of overwriting.
  - Out of chain: the pattern is the cbm-package-authorship skill
    (/bisos/git/bxRepos/bisos/defaults/ai-templates/mother/_skills/, under git); the shared-code
    duplication and two framework findings are in AI-Outputs.org (blee-binders/evolution, under git).
